## 为什么要做 Alluvial Editor？

灵感来自于 [Typora](https://typora.io/)。



本人很喜欢这个所见即所得的编辑器，其输入和输出的一致性，能让我体会到书写的快乐。这种交互就像是传统的纸笔交互——你的一笔一画都会变成画布上的内容——这也是我为什么不喜欢 Windows Doc。

> PS. 笔者在使用 Typora 之前最喜欢用的文本编辑器是 windows 的记事本。



随着对 Typora 的使用不断深入，我使用 Typora 管理我的所思所想和专业知识。并利用 Markdown 的语言特性，实现了 ToDo List —— 这极大提高了我对自我的理解和掌控程度。我可以知道自己在想什么，也可以知道过去的自己在想什么 —— 如果是零散的数据，在回顾的时候，光是整理就足够恼人了。



但是 Typora 并不是万灵药。随着我的数据量不断攀升，Typora 的功能开始摸到天花板—— 无论如何它只是一个 WYSIWYG Markdown Editor，**你并不能在其中设置一个 ToDo，在未来就真的会有物联智能来提醒你应该做什么事情**；你也不能在某个项目（Project）中设置了项目阻碍（ToDo），而没法很好的和其他项目协同处理。而且，如果我想把这样的体验带到 Web 端，这一就是一款不可移植的闭源软件。



所以，为了能够让这种所见即所得（WYSIWYG）能够从 Markdown 拓展到其他，我决定自己开发属于自己的编辑器——「Alluvial Editor」。



## 做了哪些事情？

目前，Alluvial Editor 还是没能完全覆盖 Typora 的功能点。我没有想到开发编辑器的难度如此巨大，以至于我很难想象为什么大家不愿意为编辑器付费——这些开发人员应该如何生存。



目前，Alluvial Editor 实现了部分 Markdown WYSIWYG 的功能，包括 Header、List、URL、IMAGE、CodeBlock 等。也支持了内容解析，可以直接保存为 Markdown 文件。除了 Editor 本身的编辑功能外，Alluvial Editor 在系统上也支持了前后端交互，可以将本地的 Markdown 笔记库直接发布到 Web 让其他人看见。同时，也通过 Webview 实现了 桌面应用 版本。



可以说，现在的编辑器，是一个可以编辑的编辑器了——你可以初步体验 WYSIWYG 的快乐，也可以保存，也可以再次打开、读取。



## 存在哪些问题？

当然，编辑器本身还存在诸多 BUG —— 这也是我提到的，编辑器开发困难的地方。一方面是我依赖的底层架构设计复杂，具有门槛。另一方面是笔者本身并不是前端出生，开发经验上确实有所欠缺。



不过上面这些问题并不是最大的问题。最大的问题有两个 —— 开放性问题和持续性问题。



所谓的「开放性问题」，就是我是否应该将自己的编辑器开发过程开放。有一个同义概念为：我是否应该将我的劳动成果开源。

而「持续性问题」则是指，我能否在未来长久的开发这款编辑器。



虽然，当今世界，伟大的编辑器如 VSCode 是开源的，但是其背后的团队，确是有微软供养的。所以他们不存在「持续性问题」。而其他编辑器，Typora 本身是收费的，Obsidian 虽然编辑器免费，但是其 Sync 、Publish 和商业使用资格都是付费的。Notion 的数据不归用户所有，其对用户数据管理收费。



虽然我也可以模仿这样的商业模式，那我依旧需要一款 MVP 展示其功能成果，这款产品就是 「Tidal」。但是「Tidal」 的开发也需要时间。



再回到「开放性问题」上，根据经验，如果持续性存在问题，一般就不应该选择开放——这和开放的环境和底气都有很大的关系。
