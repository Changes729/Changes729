# 标签化

后端对数据进行管理。



## 标签管理器（TokenManager）

标签管理器用来统一管理所有文件系统的标签。类似于定义一个总数据库。所有的标签具有统一抽象的行为。可以通过标签管理器进行配置，装卸载。

所有标签都有针对文件系统的实现，主要实现 读取器 `Reader` 和 写入器 `Write` 。

- 读取器：从文件系统中读取标签。
- 写入器：从标签系统专项文件系统的标签。

当前端与后端交互时。后端会回给前端标签加载器（Token Loader）。前端可以组合各种标签加载器最终实现内容的匹配（Matcher），然后进一步通过匹配的内容，实现 读取和写入。

当然，也提供了路径具名查找器。





### 日期标签（DateTime）

日期标签提供宽范畴的时间相关文件管理。

我们使用 `YYYY-MM-DD HH:MM:SS Z` 的方式管理文件日期。同时，日期是一个范围。可以通过范围的 并 `&` 操作，了解时间的宽范围，或者周期范围。

- `YYYY`：表示某年
- `YYYY-MM`：表示某年某月
- `MM`：表示年周期性的某月
- `MM HH:MM`：表示年周期性的某月某小时分钟。



在具体文件管理上，日期标签的读取有两种不同的方案，分别是，文件名识别（File Name）和 文件夹标签（Dir Name）。通过树状结构进行管理。



日期标签的读取，通过顺从文件夹的树状结构，并兼容系统环境、文件夹继承、文件名称的方式逐一确定。

日期标签的写入会比较麻烦。因为文件数量少的情况下，所有文件通过具名的方式构成文件树会非常明晰。如：

```txt
2025-11-2.md
2021-10-29.md
```

但是如果文件一多，还是用文件管理起来会方便很多：

```
2025
|-- 11-2.md
|-- 10
	|-- 3.md
	|-- 4.md
2021-10-29.md
```

具体内容需要通过管理器进一步配置。



### 文件类型标签（File Type）

对文件类型提供了后缀标签。

后缀标签的读取和识别，一般遵循文件后缀名。未来可能会提供自动类型检测。



### 具名内容标签（Named）

我们目前只支持 具名的内容标签，比如一篇文章的标题，一幅图片的名称等等。暂时不支持文件夹标签，是因为文件夹的标签树需要进一步被结构化定义。



## 标签组合

标签是可以组合的。相关组合也需要在标签管理器中设定。

比如我们设定：`Datetime->fileType`，那么文件就会类似：

```txt
2025-10-1.md
2021-10-29.md
```

而如果设定了 `named`，那么就会有具名的文件：

```txt
2025年的国庆节.md
```

在系统中，我们会把相同的两个文件绑定，也就意味着 `2025-10-1.md` 和 `2025年的国庆节.md` 实际上是同一个文件。

更进一步，如果标签组合设定为：`Datetime->fileType->named`，那么文件就会这样存储：

```
2025-10-1/
|-- 2025年的国庆节.md
2021-10-29.md
```

如果同时设置了 `Datetime->fileType->named` 和 `named`，那么就会同时存在两种存储。需要提及的是，多种标签存储并不会导致文件拷贝（Copy）。
