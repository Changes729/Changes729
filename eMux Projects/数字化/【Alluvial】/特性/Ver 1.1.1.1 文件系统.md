# 文件系统

我们最开始设计标签化系统，是为了通过文件系统，文件夹的树状线性管理方式，直接得出我们对文件的标签概念。

因此，我们设计了 `TokenSeries` 以从文件的角度，反向识别操作系统的标签链表。并允许 硬连接，使得我们拥有了从文件的角度获取的标签树。



然而，我们现在回过头来，可以意识到，文件或者说工程，是有树结构的。这就意味着，从文件视角所拥有的标签树，很可能，从文件系统视角是一个工程内容。



## 已有标签系统设计

假设我们有一个文件系统设计如下：

```txt
/[root]
|-- 日志
	|-- 2025-10-1/
		|-- 2025年的国庆节.md
		2021-10-29.md
|-- 笔记
	|-- 2025年的国庆节.md
```

虽然我们可以知道，`日志` 是一个 `Datetime-named-type` 类型的文件系统，而 `笔记` 是一个 `named-type` 类型的系统，可是我们如何处理两者在同一文件内部的关系呢？



## 文件视角

其实，从标签系统可以进一步区分，`Datetime` 是一个兼具命名的标签系统，在上述案例中，这个命名功能并没有体现。所以，如果我们将 `Datetime` 视作一个工程化的东西，这样我们就大致可以得到，`DatetimeProject` 下的 `named-type` 文件。



那么如何进一步把 `日志` 引入呢？特别的，如何把 `[root]` 引入呢？

可以先列举一下，假设我们把 `[root]` 视作一个项目，那么就会得到两条路径：`[root]-日志-Datetime-named-type` 和`[root]-笔记-named-type`。这就意味着，从 `[root]` 视角产生了分叉。



## 已有描述

当下，我们把从文件视角产生的标签系统，命名为 `TokenSeries`，那么，如果从文件系统视角（目录视角）形成的标签树，是否也能用同样的方式继承呢？

```txt
/[root]
|s--[日志]
	|s-- Datetime-named-type
|s--[笔记]
	|s-- named-type
```
